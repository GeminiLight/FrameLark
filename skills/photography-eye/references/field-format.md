# 现场输出：用户拿着相机就能做

适用：完整勘景、具体机位追问、复拍辅导。下面是默认形态，可随现场缩短，不是每次必须填满的表格。

普通现场问法先给一张主推：两三步动作、当前器材需要的设置、一个检查点。完整图板模式沿用用户已经表达的偏好；不要为了形式同时展开所有候选、两份器材教程和练习。文字起手让用户先拍，不等图生成。

## 一次完整勘景
<!-- knowledge-id: field-format#1 -->

先用一至两句交代主推和依据。例如「先拍 P1 跑道与远处人物：白线已经形成弯曲路径，先保住人和天空的关系。用现在的位置试一张，再比较侧移。」

完整交付按「立即主推动作 → 精修目标主图与候选参考板 → 逐张拍法＋后期卡 → 复拍任务」组织。每格有机位/角度、拍摄参数和一行后期方向；图外文字独立能执行。动态图景先给即时拍摄动作，后期展开随后补，不能让用户错过瞬间。

完整图板默认P1主推加P2–P5四个候选。每张文字先说明值得拍的关系与相比随手照的取舍，再给动作；「换位试拍」与「当前可拍」在图片和文字都标清。五张不代表都要拍完，用户可以直接选最喜欢的一张开始。

内部先整理完整的图文方案再生图；默认一次调用生成一张完整板，避免逐张生成后拼装。展示顺序不改变这项准备顺序。

主推用一个完整动作卡，信息顺序贴近操作：

| 字段 | 要回答的内容 |
| --- | --- |
| 拍出来是什么 | 主体关系、景别、画幅与预期阅读；区别可见关系和预期效果 |
| 站哪里 | 从当前视点出发，借助明确地标，左右/前后如何移动；标清近似起点 |
| 相机怎么放 | 高度与姿态、朝向、俯仰、横竖拍；高度指镜头/相机，不只是身体蹲下 |
| 屏幕里怎么取 | 主体、线条、前中后景、画面边界；哪些元素保留、哪些靠取景排除 |
| 参数起点 | 已知器材内的焦段、曝光模式、光圈或快门优先、ISO策略、补偿触发条件 |
| 对焦和瞬间 | 可辨认对焦目标、静态/连续对焦；哪个动作或间隙出现时按快门 |
| 调色与精修 | 先给一项优先调整＋成功标志；再按需要补白平衡/调性、具体颜色、局部位置、材质处理。数字标软件和基准，给过头回退；没有局部工具时可保留原样 |
| 如果不对 | 一种常见失败与具体修正；用画面现象作停止条件 |

其他方向逐张给短卡：**编号/名称｜成片与理由｜站位｜高度/角度/画幅｜取景与对焦｜拍摄参数｜瞬间/成立条件｜后期先做哪一项｜检查与回退**。共用器材或调色骨架可以放开头；每张拍摄控制和局部精修仍写清，其余调整只在对应问题出现时展开。更换主体/尺度/时间关系，而不是凑同构图的小变化。

图文必须一一对应：同一编号使用相同名字、源图、表达目标和参数。图中为了易读省略的条件在文字补齐；不能图里写f/4、文字写f/8，却不解释两种用途。每个卡片只保留当前方案需要的设置，避免将一份通用参数表贴在所有图上。

最后给一个立即执行的动作。可以让用户在同位置比较站立、半蹲两张；若当下动作很快，只拍主推一张，别为了练习错过瞬间。

## 走位的语言
<!-- knowledge-id: field-format#2 -->

从每张方案的第一步说起：原地取景、走到可辨认位置、降低镜头、换焦点或检查等待条件。当前取框四边绑定可见物体；新机位说明动作如何改变前后景、遮挡和边界；等待方案说什么现象出现时拍、没出现怎么办。它们可以独立成为主推或候选，不强迫先交一张原片裁剪。原片框、换机位试拍与未来条件分别标注。

一张卡可以先现在拍，再试调整或等事件，但分开写。例如“当前位置先拍白线与两人；再将镜头降低一点，只有屏幕里人物与背景真的分开才保留新视点；若手臂随后离开身体，再补一张”。降低镜头也改变视点，不能把整段都标为“原片裁剪、无需改变机位”。

- 「左/右」相对当前面向的场景，并用地标确认，例如「朝画面左边那段草带的近端移动」。多张图方向不一致时标清来源。
- 距离是**试拍范围**而非测距：「先侧移半步，看人物头顶与灯杆是否分开」。更长移动用地标终点：「沿现有路面向前，直到跑道文字出现在你身后」，不把看不到的路况当作确定。
- 高度可以说「镜头先降到约膝盖高」「试约 50–70cm」，再说明取景条件。并非越低越好，升高也能使前景从遮挡变成路径。
- 给俯角时说明参照：镜头朝向相对水平线，0°近水平、90°近正俯；只作试拍起点。高度与俯角不是同一变量，最后看主体遮挡、盘形和前后层是否达到目标，不把标签当已测量角度。
- 相机朝向绑定可见目标：沿草带延伸方向、略向上保留云、接近水平保留建筑竖线。不知道方位就不用东南西北。
- 始终把视点移动和变焦分开：先固定焦段处理遮挡关系，再变焦控制边界；当用户不能移动，改用当前可见范围中的拍法。

## 追问「第 3 个怎么拍」
<!-- knowledge-id: field-format#3 -->

保留原来的 P3 名称、对应源图和目标。先复述「P3 草带斜线」，然后把站位、高度、朝向拆成两至四个动作，最后给一个屏幕检查点与参数差异。不要重新列全部方案。

用户说「蹲下什么都拍不到」时，把其反馈当作新证据：可能是过近、过低、线条投影不成立或对焦范围限制。优先后退/抬高/侧移的验证，而不是重复贴地指令。

## 复拍一轮
<!-- knowledge-id: field-format#4 -->

1. 实际读新图，对照同一方案目标，指出已成立的一处变化。
2. 只找阻碍该目标的最重要差别：主次、重叠、边界、光线、时机、运动或焦点。
3. 给下一项动作和成功标志。用户改完不一定更好；目标已经达成就停。
4. 新现场或新意图更换方案时显式说明。时间窗已消失，就基于最新图重选方向。

## 光线正在变化
<!-- knowledge-id: field-format#5 -->

先交付十几秒可读的版本：**主推 → 位置/取景 → 关键参数策略 → 按快门条件**。在用户确认晚霞已出现时优先原地拍，不先安排远路或等待数分钟的参考图生成。不要把来源不明的旧图当此刻天气。

## 项目需要结构化数据时
<!-- knowledge-id: field-format#6 -->

普通对话输出自然中文。接口或页面明确需要机器可读结果时，可使用这些语义字段，不要求在聊天里展示 JSON：

```json
{
  "sceneId": "scene-a",
  "sourceImageIds": ["image-a"],
  "mode": "scout",
  "observations": [{"location": "左下", "evidence": "可见的画面关系"}],
  "assumptions": ["设备或可达性尚未确认的条件"],
  "recommendedPlanId": "P1",
  "plans": [{
    "id": "P1",
    "name": "画面关系名称",
    "viewpoint": "current",
    "timing": "now",
    "conditions": [],
    "captureChanges": ["该动作造成的透视、遮挡、焦点或光影变化"],
    "conditionalVariant": null,
    "expectedFrame": "预期组织方式",
    "position": {"anchor": "可辨认地标", "movement": "动作及停止标志", "cameraHeight": "近似起点"},
    "framing": {"orientation": "portrait", "aspectRatio": null, "sourceBox": null, "keep": [], "excludeByFraming": []},
    "settings": {"deviceBranch": "camera", "focalBasis": "lens-marking", "focalLengthMm": null, "mode": "A", "aperture": null, "shutterPolicy": "条件起点", "isoPolicy": "自动或明确设置", "compensationPolicy": "何时调整"},
    "focusTarget": "可见目标",
    "trigger": "按快门的条件",
    "verify": "取景屏与试片检查",
    "fallback": "失败后的动作",
    "finishing": {"status": "planned", "lookIntent": "成片光色与材质关系", "toolBasis": "软件未知先给方向", "global": [], "color": [], "local": [], "detail": [], "verify": [], "fallback": "过头先撤哪一项", "captureDependencies": [], "untransferableFromReference": []},
    "visual": {"kind": "none", "path": null, "label": "无视觉参考"}
  }],
  "nextAction": "立即可执行动作"
}
```

这是设计约定而非已实现服务契约。未知量用 null/条件描述，不把焦段、距离和日落时刻猜进数值字段。`visual.kind` 可为 `none`、`source-annotation`、`source-crop`、`generated-concept`；后两者不是新机位实拍。

`viewpoint` 为 `current/test`，`timing` 为 `now/conditional`，分别表达视点是否已见和是否需等待。试探与等待可以直接成为独立方案；`conditions`、`captureChanges`、`trigger`和`fallback`写成立条件、动作效果与退法。`conditionalVariant`仅用于该方案附带的小变体。`sourceBox`只对应当前原片，新机位为空；有框时注明源图尺寸并复核宽高比。

`finishing.status`可为planned/executed/verified，分别表示建议、实际处理、实际修后结果通过明确检查；看过但检查失败仍为executed并记录问题。生成目标图不升级为executed。`visual.kind`增加generated-finish-target（含后期意图的生成概念）与actual-retouch（实际原片处理结果），两者不得混称。
