# 精修工具运行契约

此页随 Skill 一同分发，适用于本机工具的能力选择、限制和可信源码扩展。运行目录与参数以当前工具实际返回为准。

## 本地运行与扩展

### 按项目协议选工具

`inspect` 返回 `editProtocol`。旧配方使用 `photo-tools`/`compose`，注册定义在 `scripts/engine/photo-tools/registry.js`，保存可独立取舍的效果与工具执行记录。已启用的新栈使用 `document-tools`/`document`，保存稳定步骤、版本化蒙版和顺序；RAW 项目从导入成功时就使用新栈。两类参数语义不同，不能通过旧 settings 覆盖新步骤。

方案固定项目版本与 revision；文档提案还固定 documentRevision/baseHash。依赖、选择身份、审核、锁与最终像素保护继续校验。候选不会自动接受，取消与失败保留已保存版本，原片字节不写回。哈希验证的是内容身份，不证明宿主看过图片或审美已通过。

### 旧工具组合的执行限制

旧目录中的操作只能调用注册的可信工具。目标可指向整张、明确区域、带几何蒙版的对象、批注或前一工具产生的范围。名称本身不分割天空/人物；坐标和身份来源需明确，实际检查蒙版边界。蒙版与局部能力以工具目录为准，不声称精准语义选区。

工具方案最多 24 项；效果与既有局部合计最多 8 处。依赖必须存在并被选中，同一写入路径的多项操作要声明先后。选择变化从固定基础重算，不在上一张预览上反复累加。

`compose` 用固定 Node worker 为每个选中工具启动独立子进程。默认单步 30 秒、整组 120 秒，输入/返回分别限 8 MiB/4 MiB；取消或超时终止子进程。执行记录与中间 PNG 是实际结果。进程隔离管理任务生命周期和错误，不是不可信代码的操作系统沙箱。

### 新栈与 RAW

新栈的步骤、蒙版、资源和像素预算由 `document-tools` 返回。现有步骤按稳定 ID 修改，真实依赖不能被破坏，删除依赖生产者默认拒绝；只有明确的 cascade 才连带删除。接受与导出继续使用同一份项目。

普通栅格源和旧兼容基础有 8 位边界；Float32 不会补回输入缺失的信息。RAW 通过固定后端保留线性高精度数据，新栈分块渲染，master 可输出当前裁剪的原尺寸 16 位 sRGB TIFF。机型/压缩方式仍须实际解码验证，不把预览 PNG 的位深当成 RAW 母版精度。详见 [可编辑栈](editable-stack.md) 和 [导出参考](tools.md#版本与导出)。

### 扩展只来自可信源码

工具定义声明稳定 id/version、说明、支持目标与严格参数 Schema，返回可保存、可重放的效果；需要异步执行时，还须保证实际结果与预先声明一致。新工具必须在本 Skill 的可信注册表中注册，并验证参数、依赖、像素、取消和接受行为。超出现有效果类型时需要实现对应渲染支持。

模型不能上传代码、指定 shell、模块路径或任意可执行文件。历史执行记录也不是重新执行的授权；重放必须通过当前目录、版本与目标校验。这里的本机能力不等于云端或浏览器内联执行能力。
