# 从接受与回退中积累知识

## 三种知识不能混为一谈

- **通用方法**：工具语义、可复用处理逻辑和真实质量检查。能通过代码、正式文档或多次可复现观察校验。
- **这一张的判断**：实际可见关系、当前意图与候选代价；只在该照片、该版本和该观看条件下成立。
- **个人偏好假设**：多次明确接受、回退及说明形成的倾向。不能从一次点击推导“用户永远喜欢暖色”。

同一用户可以在人像要真实，在夜景要浓烈，在纪实要保留粗糙。当前意图 > 明确本次反馈 > 同场景已接受选择 > 更早的偏好假设 > 默认风格。

## 接受什么才算学到

本地工具在 accept 时记录 choices；临时悬停、试片、取消与生成候选不是认可。accept 可能只表示这次可用，不证明全部参数都是偏好。需要结合选择理由及原片条件。

`accept --by agent` 保存 Agent 试修，不写入用户 choices。明确用户反馈用 `feedback`；拒绝或仅作试片保留的版本不进入 `preferenceChoices`。历史 choices 不删除，实际偏好参考使用 `inspect` 返回的 preferenceChoices；工具成功、Agent 选出的最佳版和用户认可各有不同证据。

有价值的记录包括：

- 原片题材与可见光线；已知来源与显示条件。
- 接受前/后版本、实际参数、风格强度、范围与裁剪。
- 当前表达目标；用户明确喜欢什么、拒绝什么。
- 付出的代价；哪些效果只在窗口预览看过，哪些检查过细节/导出。
- 下一张何时可复用，何时必须重新判断。

示例：“逆光户外肖像，用户接受轻提脸部但退回暖色；下一次类似光线先保留真实肤色，不能据此推断所有风景都偏冷。”

## 回退是重要证据

用户取消说明不合适或无收益，也可能只是换创作方向。把原因记成具体现象：天空条带、肤色过橘、背景变亮、裁剪失去落脚点、风格不符合本次目标。不能只记“AI 失败”，更不能用取消记录增加相同风格推荐。

保留原片也可是一项成功判断。停止条件是目标达到或改动无可见收益，不是参数越多越好。

## 本项目与可携带档案

项目内使用 inspect 返回的 preferenceChoices。可携带档案通过 profile 命令明确建立、学习和读取；不会后台自动训练模型。

只有用户要求建立可携带偏好档案时，才在其指定的本地位置整理。使用 `profile-init --profile <new-file>` 建立档案，`profile-learn --project <folder> --profile <file> --input <JSON>` 输入 revision、versionId、subject、lighting、reason。只有用户明确接受/喜欢或拒绝的已保存版可以学习；Agent 试修不作为偏好。证据绑定项目、源图、版本、参数身份和明确理由，重复证据去重，同版本后续拒绝替换先前喜欢。用户后来标为 neutral 时，再运行 learn 会移出该版已有偏好，不新增记录；项目反馈变化后，应明确同步相应档案。

`profile-read --subject --lighting` 返回匹配条件，当前意图优先，不自动套参数。`profile-edit --input {id,subject,lighting,reason}` 修改条件或理由，`{id,remove:true}` 删除。题材和光线说明最多各 120 字，理由最多 600 字；读取与保存使用同一 8 MiB 字节上限，超限修改不覆盖原档案。最多 500 条，不包含照片或模型 Key；用户理由可能私密，档案默认不发布。无需把私人原片嵌入公共 Skill。技能成长记录与个人照片分开，不把用户名、私密批注或 API Key 写入分发包。

## 知识升级门槛

新方法加入通用参考前满足以下条件：

1. 已明确问题、意图和工具版本；保留原片与可复现的绝对参数。
2. 看到实际输出，而不是仅凭执行成功或统计提高。
3. 对照至少一个容易误用的情境，给出回退条件。
4. 把官方事实、工具事实、视觉解释与推测分开。
5. 经过多种样本才提升为通用规则；只有一个案例时保持“该案例观察”。

视频结论需分别标注播放、帧、音频和元数据覆盖范围。没有声音或连续播放审阅的案例不能升级成“节奏/同步已通过”。

成长反馈围绕可实践的观察：怎样识别主光、如何保留色光、为什么这次不裁剪。避免无依据的百分制成长曲线、人格标签和默认排名。
