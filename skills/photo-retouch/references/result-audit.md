# 成片审核与返修

适用：用户指出修得不够、成片不好看，或要求先审核再继续调整。审核由实际看图的宿主 Agent 完成；本地工具核对版本和预览身份、保存结论，不自动给照片打审美分。

## 先看结果再判断

从用户最后看到的失败版开始，指出仍存在的位置与视觉关系。原片柔软、天气平淡或素材复杂，都不能代替检查自己的处理。将目标写成可检查的观看顺序，例如：先看到船，再读到岸，枝叶承担框景。

每轮查看完整画面，以及主体、明亮平滑区域和高反差/蒙版边缘。实际导出还要单独复看；预览与导出尺寸不同时，说明各自的检查倍率。审核不能依据参数表、直方图、文件 hash 或工具成功推断好看。

## 审核问题的优先顺序

创作型组图还须按 [主题驱动的组图](theme-led-series.md) 分别判断单张与整组。某张缺少具体吸引力、精修后仍不符合主题，或实际九格的观看关系不成立，均不能以“内容多样”“颜色自然”“没有伪影”判 ready。精致是当前明确目标时，相关阻碍不能全部降成 minor；必要时换备选。独立复审须检查同一目标，审片者一致同意不代表用户满意。

按 [成片执行卡](finishing-workflow.md) 逐项复核原来的成片目标。明显改善仍不足以放行：原目标未达到，就保留为返修。`minor` 仅指不影响当前表达与交付的细节；不能事后改写目标，把仍然抢眼的天幕、不可读的人物或缺少体积的杯身重新解释为成功。审照片时先去掉说明、IP 和漂亮排版，设计质量另行判断。

| 观察 | 判断与返修 |
| --- | --- |
| 观看重点仍被大面积前景压住 | 比较更收紧的裁剪，或局部改变主次。原来已经轻裁不代表构图完成；删除的地点信息、肢体、框景及叙事关系须说明 |
| 全图有变化，主体仍不清楚 | 调整主体尺度或主体与环境的亮暗/色彩分离。全局清晰度不能解决所有位置，局部范围须宽缓并复看背景 |
| 天空、水面、地面一样亮或一样灰 | 重新决定每层的重量与空间角色，必要时分开渐变；检查灰脏高光、亮斑、交界或抬亮的遮挡 |
| 风格名成立，材料和颜色关系不成立 | 从具体色块检查：天空是否偏紫、白墙是否泛黄、肤色是否异常；重做光色关系或撤掉不适配预设 |
| 锐化、降噪或蒙版变得可见 | 回退造成伪影的处理，检查实际输出的细节和边缘；不能用更多处理掩盖过度处理 |

先修阻碍表达的问题，再修细节。改动可大也可小，由问题决定；不能把“最小处理”理解成所有参数必须低强度。发现构图问题时允许实质裁剪，保留可恢复原片并说明损失。

## 记录决定并继续修改

用 `result-audit --input <audit.json>` 保存针对固定版的审核。输入含实际 `preview` 返回的 pixelHash、frameSpecHash、selectionHash、相同 maxSide 与最新 revision；不使用联系图、区域图、无字版或不同参考裁剪的身份充当完整成片身份。工具重新渲染并核对，但 hash 不证明宿主真的看过图。

```json
{
  "revision": 12,
  "versionId": "候选的真实ID",
  "maxSide": 2000,
  "pixelHash": "实际完整预览返回的hash",
  "frameSpecHash": "实际预览返回的hash",
  "selectionHash": "实际预览返回的hash或null",
  "decision": "revise",
  "summary": "裁剪已经集中主体，但天空过灰，船仍与岸混在一起，继续返修。",
  "checked": ["完整画面：船、岸、框景的观看顺序", "船边缘、平滑天空及局部过渡"],
  "strengths": ["完整船体与水面留白仍在"],
  "issues": [{"area":"上部天空","observation":"亮度被压得接近远岸，天空呈灰块，失去空气层次","nextAction":"回退天空渐变的曝光压缩，保留天空亮度；检查白墙和叶缘","severity":"blocking"}]
}
```

- **revise**：有可修的问题。根据每个 nextAction 修改已看过的试片，再生成新预览、重新审核；旧审核保留说明为何返修。
- **reject**：方向不成立。取消候选，回到有依据的基础重做，不累计补偿参数。
- **ready**：当前表达目标已达到，没有 blocking 问题；记录仍有的 minor 问题和取舍。ready 是 Agent 的有条件判断，不是用户已经认可。

在未接受候选上继续精调可用 fromCandidate，完整继承其层；或基于固定基础写完整绝对目标，不混用两种语义。组合勾选或参数改变后，旧审核不能为新像素背书。

Agent 自动保存交付方案时使用 `accept --by agent --require-audit true`，同时填写最新 revision 和 selectionHash。此开关要求该组合最新审核为 ready；缺审核、revise/reject 或组合身份不符会阻止这次保存。人工主动接受仍可按原流程使用；工具没有偷偷全局强制审美审核。

## 收尾与适用边界

通常两到三轮有针对性的修改即可看出方向是否成立。仍有 blocking 问题就明确保留为未完成试修，不为了交付将问题改写成 minor。没有收益应撤回，不能无限添加处理。

交付时给成片、审核中最关键的问题、实际修正与剩余取舍。测试通过只证明工具行为；审核 ready 只适用于注明的目标、画幅与检查范围。用户后续否定时记录明确 feedback，并重新审阅用户看到的结果。
