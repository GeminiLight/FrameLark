# 光色定调与试片验收

适用：用户说不好看、风格平庸、希望更精致，或几个方向看起来几乎一样。搜索：定调、调色、试片、色彩关系、胶片、绿叶、look-sheet。

## 从画面建立一个可见方向

“自然”“高级”“胶片”还不足以指导修片。把方向写成能在原片和试片中指认的关系：前景深绿与冷水面，暖色船体作为点缀；或柔和浅绿与温润中间调。说明观看重点和一项要保留的关系，不要求用户先懂参数。

原片已经有好的光色关系时可以保留。用户拒绝上一版，则先看失败版：是焦点依然分散、颜色不协调、层次发灰、处理过硬，还是这套情绪不符合他的意图？器材、地点与天气未知时不补编。不能用“原片有限”代替检查自己的处理。

先以当前图建立关系，再参考风格或作品。人名不能证明试片好看。精准参考需要实际看参考；普通试片可以用“温润淡彩”“深色框景”等描述，不虚称大师同款。

## 光色和构图分开比较

用户只表达“不好看”时，通常先保留原构图试一个明确方向；需要澄清时询问温暖柔和、冷静浓郁还是自然通透，或邀请给参考图。已有意图就继续，不每张都发审美问卷。

用相同基础版本创建最多两个有区别的光色方向，不能一版裁剪、一版改颜色后把整个收益归给风格。候选的绝对目标独立计算；不把前一份试片的补偿叠进下一份。

`look-sheet` 的 `color` 模式以同一裁剪与倍率比较原片和候选；`composition` 模式保留各自画幅，并显示保留面积。看整张再看关键局部，联系图仅用于方向选择。

裁剪应另作可撤回项目。先说移除了什么、失去了什么。切掉约四成面积就不称为“轻裁”；固定比例不能证明更好。原构图中的遮挡、距离和留白可能就是照片的表达。

## 让参数服务于光色关系

- **明暗层次**：先决定哪一层应有重量、哪一层应可读。全局提阴影会同时显露杂乱枝叶，压黑位又可能把这次提亮抵消；用实际对照判断是否需要两者，不为了完整专业面板填参数。
- **综合色调**：白平衡先处理有依据的偏色；有意调暖或调冷则检查中性物、天空与材料。混合光不能靠一个全局色温同时校正。当前 warmth/tint 是相对增益。
- **主辅色**：先确定大面积主色和小面积锚点。大量绿叶抢眼时，可以调整绿色综合的色相、饱和度和亮度，同时让船体、建筑或人物的颜色保留分量；全局降饱和会把这些锚点也削弱。
- **控制真实范围**：本引擎 greenHue 围绕 125°、blueHue 围绕 220°、orangeHue 围绕 30°加权，色相参数在中心最大位移为数值 × 0.5°。黄绿色、青色与橘色的响应不等强，不能因为写了 greenSaturation:-20 就声称所有叶片都降了 20%。首次试方向要实际看结果。
- **形成可辨的风格**：很多 ±2～5 的改动可能仍然无明确方向。先试能看出目标关系的强度，再回调到材料可信、层次自然的位置。变化明显不等于更好；低强度也不自动精致。
- **风格层**：已有预设做情绪骨架，手动层只适配这一张。不要把预设配方重复写入 settings，也不要用大幅相反参数抵消不适配的风格；优先降低强度或改选方向。
- **质感**：颗粒、抬黑、暗角与强微反差均需独立理由。柔和并不等于全图灰，深色并不等于全图黑；失焦树叶不能由锐化变成新的真实细节。

## 题材中的正向处理线索

以下是处理假设，不是固定配方或自动评分：

| 原片条件与目标 | 可以试的关系 | 必须检查的代价 |
| --- | --- | --- |
| 日光下大量绿叶，希望温润淡彩 | 温和暖色中间调，减少黄绿的躁动，水面保留相对冷色，小面积暖色仍可辨 | 白墙泛黄、天空发灰、枝叶被提得过平；阴天没有暖光依据时别声称恢复夕阳 |
| 暗色框景与明亮远景，希望安静纵深 | 深色前景保留重量，远景保持空气透视，主体只提升必要的分离 | 前景堵塞、对岸锐化白边，暗角再次压重已有框景 |
| 人像柔光，希望细腻真实 | 肤色和环境综合色调协调，宽缓高光，中间调保留表情与肤质 | 橘脸、漂白、额头灰脏、皮肤纹理涂抹；不沿用风景绿色综合配方 |
| 夜间暖灯与冷环境，希望色光层次 | 让灯和环境保持各自的颜色，保留暗部及关键轮廓 | 灯芯颜色剪切、暗处蓝紫噪点；不套白天提亮方案 |
| 雾、雨或反射，希望柔和空间 | 保留弱反差层，近处建立少量深色锚点，色彩面积有主次 | 全局去雾破坏距离、抬黑又抵消锚点、湿玻璃误当清晰度缺陷 |

## 对实际试片作取舍

对每个方向写下：**看到了什么变化 → 是否帮助当前意图 → 引入什么代价 → 保留、继续细调或撤回**。不能以执行成功、色彩统计变化、尺寸检查或无光晕代替审美判断。

如果两版在正常观看尺寸下几乎一样，不给它们硬贴两个风格名字。继续细调最有潜力的一个方向；看不到可解释的收益就保留原片，并清楚说明哪里仍未解决。不要为了交付成片自动宣布“明显更高级”。

关键检查：主体与环境的色彩关系、白墙/皮肤等可信材料、天空过渡、暗部重量、高反差边缘、几何局部的边界。复看实际导出，注明检查倍率与输出尺寸；当前输出上限并非原片全分辨率。

Agent 为交付试片执行保存时用 `accept --by agent`，这会保留可恢复版本并允许导出，但不会形成用户偏好。用户明确接受才用默认 `--by user`；收到明确拒绝时用 `feedback` 记录其原话与对应版本。后续偏好只参考 `preferenceChoices`，历史 `choices` 仍保留作为操作记录。

## 比较与反馈工具

```text
node <skill>/scripts/cli.mjs look-sheet --project <project> --input <sheet.json>
```

```json
{"revision":12,"versions":["original","候选A的真实ID","候选B的真实ID"],"mode":"color","referenceVersion":"original"}
```

`composition` 不传 referenceVersion。比较不会接受候选或改变编辑记录。过期候选拒绝；某版无法预览会显示错误和 complete:false，不能把缺图联系表称为完成验收。返回的版本、selectionHash、像素身份与画幅用于复核同一份试片。

```json
{"revision":15,"versionId":"已保存版本的真实ID","verdict":"reject","reason":"用户明确反馈：颜色不自然，裁剪失去包围感"}
```

用 `feedback --input` 提交；verdict 支持 reject/prefer/neutral，必须对应用户明确表达。拒绝或仅作试片保留的版本从 `preferenceChoices` 排除，不删除历史，不改像素。用户后来明确更喜欢这版，可记录 prefer；不能把 Agent 自己的选择写成用户反馈。
