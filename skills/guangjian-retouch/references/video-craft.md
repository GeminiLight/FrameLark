# 视频：调色、镜头衔接与剪辑判断

## 能力分流

本 Skill 的本地图片 CLI **只处理静态照片**，不支持视频导入、时间线、声音、跟踪、逐帧蒙版或视频导出。视频任务先检查宿主实际能读什么、有哪些剪辑/媒体工具，再执行可用流程；不能把调过的一张截图交付成“视频已完成”。不额外调用光间模型服务。

可以提供镜头与调色方案、分析实际读取的帧和音频，并在已存在、适合任务的外部工具里执行。能力不足时指出具体缺口并交付可用的镜头表/操作计划。不要安装大型软件、购买插件或假装启动了不存在的后台。

## 素材与色彩管理

正式调整前记录：尺寸、画幅、帧率/可变帧率、时长、方向、音轨、编码、位深、色彩原色、传递函数、矩阵和全/有限范围。记录“未知”和“未验证”，不能仅凭平淡画面判断为 Log，也不能把 Rec.2020 当作 PQ/HLG 的同义词。

- 摄像机 Log / 广色域需要明确输入配置，查对应厂商原始文档；相机型号和准确的 Log 版本不清楚时问具体问题，不猜 LUT。
- 输入转换、创作 look、镜头匹配与输出转换是不同环节。不要同时自动色彩管理、手动转换与 LUT 重复归一化。
- HDR→SDR 涉及高光映射、色域与输出观看条件，不是简单减曝光或加对比。FFmpeg 的 tonemap 有输入/线性光要求，使用前检查对应版本、zscale 可用性和完整色彩链。[FFmpeg 官方过滤器文档](https://ffmpeg.org/ffmpeg-filters.html#tonemap)
- SDR 帧导入本照片工具会进入 8 位 sRGB 工作空间，不能据此保证原视频 HDR/10 位/Log 的最终品质。抽帧只用于判断时，说明显示转换和抽帧格式的影响。
- 元数据可能错或缺失；需要结合来源与实际工具确认。电脑截图正常不等于电视/手机 HDR 输出正确。

## 观察帧，也观察时间

先列镜头边界和代表时刻，再看连续播放或足够密的时序样本。单帧不能判断运动、闪烁、节奏、口型同步或音频质量。只有帧读取能力时把这些标成待检。

每镜头检查：开头、稳定中段、结束、曝光/光源变化、人物进出和焦点转移；跨镜头检查连续动作、视线方向、空间关系和颜色跳变。蒙版或降噪只看一帧可能掩盖跟踪漂移、鬼影与闪烁。

## 镜头匹配与调色

1. 先选叙事上具有代表性、技术上可用的锚点镜头，确定肤色、黑位、亮部与主色关系。不要选择光源极端的一镜当全片标准。
2. 校正明显偏差，再做跨镜头匹配，最后试 look。夜转日、室外转室内可有合理变化，不强迫全片相同直方图。
3. 同场景同人物先匹配脸和可信中性物，再看背景；不要牺牲灯光动机让所有肤色同样亮。
4. 曝光改变可能需要关键帧，几何范围可能需要跟踪；当前照片工具没有这些能力。别把静态局部方案宣称成稳定视频蒙版。
5. 去噪检查运动纹理、头发、烟雾和拖影。时间降噪可能涂抹运动；静态照片 denoise 不能替代视频时序算法。
6. 颗粒、锐化与极端 HSL 必须检查整段及实际编码后文件。颗粒增加码率需求，条带/块状与闪烁会损害“胶片”观感。

## 剪辑：信息、情绪与连续性

先确认用途、观众和这一段要传达的变化。用户没有要求重写叙事时，先保护已有结构；不要机械制造前十秒开头或擅加煽情音乐。

| 决策 | 观察依据 | 常见误用 |
| --- | --- | --- |
| 何时切镜头 | 动作转折、信息已读完、情绪停顿、视线引导 | 一律按固定秒数切，重要动作未完成 |
| 连续动作 | 前后动作位置、速度与方向 | 错切导致跳步、反向、重复动作 |
| 改变景别 | 观众此时需要地点、关系还是细节 | 特写太早，空间与人物关系不清 |
| 插入空镜 | 补充地点、时间、状态或呼吸 | 为“高级感”加入无叙事联系素材 |
| J/L cut | 先声后画/画变声留是否帮助理解 | 未听声音却断言衔接自然 |
| 音乐节拍 | 节拍与动作/情绪是否一致 | 逐拍硬切压过人物和叙事 |
| 慢动作/加速 | 原帧率、运动信息和表达目标 | 用插帧掩盖低帧率，造成变形 |
| 转场 | 时间/空间关系需要何种提示 | 每镜头都加效果，抢走内容 |

声音先看人声可懂、底噪、突变、环境连续性和音乐遮蔽；响度按目标平台/交付规范查询，不背一个通用数字。字幕检查实际语义、阅读时长、人物/物体遮挡和平台安全区；横转竖需要逐镜头重新构图，不能中心一刀裁完。

学习与操作依据可从 Blackmagic 的 [官方剪辑、调色及 Fairlight 训练资料](https://www.blackmagicdesign.com/products/davinciresolve/training)继续查阅；没有实际读过或执行过的教程，不说已掌握或验证。

## 可用工具检查与读取示例

先检测 ffmpeg / ffprobe 或目标软件接口。下面示例使用独立输出目录和经正确引用的路径；如果 ffprobe 不存在，报告缺少工具，不能假装返回了元数据。外部源文件不覆盖。

```text
ffprobe -v error -show_format -show_streams -of json <quoted-input>
ffmpeg -hide_banner -ss <verified-seconds> -i <quoted-input> -frames:v 1 <new-frame.png>
```

第二条只是抽取一帧，默认链不能保证任意 HDR/Log 的正确显示。先确认素材/显示转换，必要时使用已验证的色彩转换链。采样时刻应来自实际时长与镜头，不硬编码为任意帧即可“全面审片”。

最终视频交付检查实际文件：时长、帧率、尺寸、颜色标记、音轨、首尾完整性、同步、切点、关键运动、字幕与编码后画质。只有技术探测通过不能替代播放审阅；只有视觉帧检查通过不能证明音频与节奏合格。
