# Frameyn · 帧映 — 与你的 Agent 一起修片

审片与对话由当前宿主的视觉模型完成；本 Skill 的工具只在本机处理原片，不调用帧映服务或其他模型 API，也不需要模型 Key。向模型提供图像仍遵循宿主的数据与额度规则。

## 开始照片项目

把下文的 `<skill>` 替换为此 SKILL.md 所在目录，`<project>` 为照片项目目录。路径用宿主 shell 的正确引用方式传入，不拼接用户文字到可执行命令中。

1. 首次运行 `node <skill>/scripts/setup.mjs`，检查 Node 20.9+ 并安装此 Skill 的固定图片处理依赖。以后运行不会重复安装。
2. 新照片：`node <skill>/scripts/cli.mjs init --image <photo> --project <new-project-directory> --intent <表达目标>`。项目目录须不存在，父目录须存在。保留源图字节，不改动输入文件。
3. 已有项目：`node <skill>/scripts/cli.mjs inspect --project <project>`。读取 `revision`、当前版本、意图、全部批注、审片记录、候选和预览路径。
4. 用宿主实际的图片读取工具查看返回的原片/当前预览。不能仅凭文件名、均值或用户评论声称已识别画面。无视觉能力时明确说明，并提供基础统计或人工调参，不伪称视觉审片。

工具命令和 JSON 结构见 [工具参考](references/tools.md)，需要编写方案或局部操作时再读取。

## 审片与候选

- 先理解这一张的意图。表达含糊且会改变方向时，问一个具体问题；当前意图优先于既往选择。
- 从主体、背景、光线、构图、视觉秩序与情绪观察。区分可见依据、解释和不确定性，不把风格口味当成技术错误。
- 建议写成「画面位置与依据 → 对当前意图的影响 → 最小处理 → 检查点与代价」。先说明值得保留的关系，按真正有用的内容展开，不靠专业术语堆砌或固定条数显得全面。
- 可以没有调整。说明值得保留的关系；不机械提亮、增色或裁剪。必要时用 `review` 保存观察与保留依据，来源写作宿主 Agent，不编造另一个模型调用。
- 首次调参读 `controls`：范围与灰卡响应来自真实引擎。曝光是 EV；色温/色调为相对增益，不是 Lightroom 开尔文。统计值不证明主体曝光错误，剪切掉的高光无法恢复。
- `candidate` 的 `settings` 是当前手动层的**绝对目标值**，不是累加量。`style` 是独立风格层；不要再把其配方写进 settings。局部 settings 是该标记局部层的绝对目标；保留其他已接受的局部。
- 新方案优先用结构化 `items`：一项说明一个可独立取舍的改动，填写 `id`、`title`、`patch` 和可选 `dependsOn`。同一写入路径不要拆成两项。`selectedItemIds` 从固定基础版本重算，不在上次预览上累加。`tool-schema` 输出可交给宿主的函数工具定义，`tool --input` 仅分派允许的 JSON 操作；当前运行时仍不调用模型 API。
- 每个方案填写刚读取的 `revision` 和 `baseVersion`。继续精调尚未接受的试片时，旧整组格式可填写 `fromCandidate`，继承所选试片的全部层并固化为相对已保存基础版本的一项；不要与 `items` 混用。用当前效果为基础，填写目标、主要取舍及自然易辨认的名称。候选不会改变当前版本。
- 查看候选实际预览，并用 `compare` 与基础版本共享范围对照。对眼睛、头发、肤色、高光与蒙版边缘，用 `preview --region --max-side 8192` 查看指定完整输出帧的准确裁片。region 不会重新渲染小区域；先核对返回的整帧尺寸、regionPixels 与 limited，不能无条件称为源图 100%。不能以工具执行成功、指标升高替代画质判断。
- 风格从当前光线和意图选择，解释成立条件与回退现象；大师名称是学习线索，不是官方配方。拍摄距离、时机、景深、长曝光等不能由调参补齐。精准参考要求实际看参考图。
- 按需要调整候选。没有可见收益时取消并保留当前效果；修正最多三轮仍未满足目标时，说明具体剩余问题与手动检查位置。不要无限追加调整或填满候选。
- 供用户预览后接受；若用户已明确授权自动完成修片，可自行接受经实际检查合格的方案。普通候选预览、比较与取消不需要重复审批。

## 用户精调与批注

`serve` 启动只监听 127.0.0.1 的本地预览。打开它返回的地址，用户可以看原片/候选对照、100%查看、平移、框选评论、设置保护范围、手动试片、接受/取消、恢复版本和导出。

对话继续在当前宿主中进行。页面没有独立模型服务，不能声称页面内自动发生 AI 对话。

- 用户说「看我刚标的地方」时重新 `inspect`，查看带编号原片、每处范围与评论，并优先回应其实际意图。
- 批注和局部蒙版分开保存：删除讨论标记不会悄悄删除已接受版本中的像素调整。
- 几何蒙版不等于语义分割。矩形或径向提亮可能影响背景；用羽化和实际对照检查过渡，不声称精准选中脸部或天空。
- 坐标属于正向原片，归一化到 0～1；裁剪与拉直不会改写原片批注坐标。工具参考中有示例。
- 用户改过照片、意图或批注后，旧候选会变为过期。重新读取和试片；不通过删批注、恢复旧版本或盲目复用旧参数绕开冲突。
- 参数锁同时固定手动值与风格后的有效值；局部层锁固定整层，均不等于锁住某块最终观感。`guards protect` 的画面保护引用已保存版本和独立原片坐标蒙版，最后合成硬核心，向选区外羽化；存在区域保护时先解除并接受预览，才能重新裁剪或拉直。旧批注 `protect` 仍仅防裁剪。
- 新增参数锁或画面保护保存一个不改像素的版本；解除操作生成试片，接受后才解除。恢复历史版本保留当前约束，冲突会拒绝；不通过恢复绕过锁。
- 接受前确认已检查的图和候选版本一致。页面有未提交参数时先生成试片或明确重置；预览失败先重试，不能把上一张画面当成最新效果。逐项候选必须提交最新 `revision` 和该组合预览的 `selectionHash`；全不选不产生新版本。用户明确取消时 `discard`；随时用 `restore` 回到命名版本。

## 文字点缀 · 可选模式

只有用户明确想在照片上加字时，才读取 [文字点缀](references/lettering.md)，使用独立 `lettering` 候选。普通审片和风格选择不加字，不把文字列入曝光、色彩等默认参数，也不按性别推断偏好。

先看当前成片的留白、主体与最新批注，再确定文案、字形、配色和位置。用户原话准确照用；短句、奶油贴纸和小标题都只是可选方向。文字层可继续精调、取消或移除，光色和原片保持独立；需要纯摄影成片时用 `export --without-text true`。

## 收尾

区域保护仅承诺同尺寸、同构图的最终 RGBA 核心一致。PNG 解码可逐字节验收，JPEG 只保证编码前一致。无字输出使用独立无字参考；管线/字体无法复现参考时停止保护输出，保留备份并显式解除后重新确认。

接受版用 `export` 导出，输出路径必须是新文件。验证实际尺寸，复看成片；若使用有损 JPEG，注意编码后的颜色和细节变化。

个人选择只从实际 `accept` 记录，不把浏览、临时试片和取消当成偏好。在同项目的后续建议中可参考 `choices`，但当前意图始终优先。首版没有跨项目自动审美画像。

有价值的反馈保留「条件、意图、可见依据、实际处理、接受/回退原因、适用边界」。新增通用知识要有复现和反例，单张案例保持案例结论；个人档案只在用户要求时建立。

交付成片与项目位置，简要说明实际变化、保留与取舍。不宣称未经验证的摄影质量、RAW、16位色彩或自动分割能力。

服务用当前运行终端停止。进程意外关闭后重新 `serve` 同一项目即可继续；编辑保存在 project.json，API/会话令牌不写入编辑记录。没有用户要求持续预览时，完成后停止自己启动的服务。
