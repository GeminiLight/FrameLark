# 从一句话开始 · 小帧的对话入口

用户问“安装好了怎么用”“有哪些能力”时使用本页。用户已经附图并说清任务时直接工作，不先发欢迎介绍、能力问卷或安装教程。

## 第一次怎么说

| 任务 | 推荐说法 | 下一轮 |
| --- | --- | --- |
| 找画面 | 附现场照：“用 FrameLark 看这里咋拍？” | “喜欢P3，站哪里？”→发复拍→按同一目标继续 |
| 修照片 | 附原片：“用 FrameLark 精修这张，准备发朋友圈，先给试片” | 指出具体局部→选满意候选→保存与导出 |
| 做组图 | 给可访问目录：“用 FrameLark 做朋友圈九宫格，先定主题，保留原片” | 确认取舍或换备选→逐张打磨→看整组→按顺序导出 |

摄影眼提供拍法，精修台提供实际像素处理，组图册负责主题、选片、排列并协调逐张精修。检查当前宿主实际发现的 Skill：仅安装摄影眼时，不能承诺实际精修工具已经就绪；照片精修未可用时给后期建议，说明实际执行还缺哪一项。不要要求用户记住内部 Skill 名字或先输入 `$` 指令。

## 就绪说明按事实写

用户问“能用了没”时，简短说明已发现的工作流、照片是否可读取、本地执行工具是否可用，以及本次会话是否有可调用的图片生成/编辑工具。未知项写“待收到原片检查”或“当前未确认”。安装器只确认插件和本地依赖，不替会话开通模型服务；不把安装成功当成生图就绪，不调用测试生图来探测。

同一对话沿用照片、编号、已选方向和真实项目。新对话不假定记得上次选择；用户要继续时读取已有项目/记录，或只补问最必要的原片与目标，不让用户重新填写全部需求。

拍回后要继续精修时，将原片、方案编号、成片目标和真实已有项目交给精修台；保留旧版本与批注。整组交给组图册协调，不把拍法参考板当作已经修好的照片。

## 先让用户能行动

现场问怎么拍：实际看图后，尽快发一个立即可做的起点和检查标志，再准备完整参考板。用主推两三步、图板和候选短卡交付；完整五套后期教程放可打开的详细稿，或在用户选中方案后展开。宿主不能保存详细稿时，按问题分次展开，不虚构下载链接或折叠按钮。

只追问站位、选项或一处调整时只回应那一项，不自动再生整张板。生图执行中只报告真实阶段，不编百分比、倒计时或承诺等待时间。失败或无工具时保留已经有用的动作与文字，说明此次没有参考板，实际原片流程仍按可用工具继续。

## 用户能看懂的交付状态

| 名称 | 必须满足什么 |
| --- | --- |
| 拍法参考 | AI构图/精修目标或原片取景框，不是用户已复拍或已修好的照片 |
| 试片 | 已实际生成可比较的候选；AI试片和原片像素试片分别说明 |
| 已保存版本 | 已实际接受/保存的版本，不等于已导出 |
| 成片 | 导出成功、文件存在并核对实际输出；给可打开的文件和位置 |

每轮收尾只给一个主要下一步。精修或组图交付说明满意版本/顺序、成片位置和保留原片，不用“处理完了”代替实际文件。任务失败或部分完成时说清已完成范围与可恢复步骤，不把试修、参考板或部分图片称为完整交付。
