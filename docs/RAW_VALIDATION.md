# RAW v1 验收记录

基线为 main `e05a57c`，已包含 #24/#25。开发先提交 [规格](specs/RAW_PIPELINE.md)，再实现平台适配、线性处理、代理和导出。

## 真实后端与像素

本机 macOS 26.5 / 25F71，rawpy 0.27.1 / LibRaw 0.22.1。使用 rawpy 仓库的公开 [Nikon NEF](https://github.com/letmaik/rawpy/blob/main/test/iss030e122639.NEF)，SHA-256 为 `5922721d13f11795557d97fdeb0a60b900086c402bc82a848ff280d15b99ffd4`，10,656,312 字节；未使用私人照片。

- Apple CIRAWFilter 解码器 7：4256 × 2832；LibRaw：4284 × 2844。有效画幅差异被固定在各自项目记录中。
- 生成的 256 × 192 Bayer DNG 通过 rawpy；本机 Apple 拒绝该生成文件时，自动选择模式回退到 rawpy。
- Apple 使用原片扩展名的只读临时硬链接。直接传 `.bin` 曾只得到 160 × 120 内嵌缩略图，现已拒绝无 RAW 解码器版本的输出。
- Apple bitmap 带内本来已是从上到下，曾重复反转行造成断层。17 × 300 已知渐变检查现在验证所有行单调、128/256 行边界连续，真实 NEF 网页预览已检查方向和连续性。
- 原片在导入、改变曝光和两种导出后 SHA-256 保持一致。TIFF metadata 为 RGB `ushort`、带 sRGB ICC、完整有效画幅；相邻 16 位级别仍可区分。
- 线性输入值 2 降低 2 EV 后为 0.5，再编码显示。不会从已裁切的 8 位代理恢复高光。
- 分块边缘取样总是读取相邻下一行，即使插值权重为零，也不会读取越界数据产生黑色断层；同一行带在横向多个分块之间复用，避免重复读取整行带。
- 分块与单网格输出一致，覆盖清晰度、锐化、颗粒、亮度范围、裁剪/旋转、范围预览和保护参考。保护快照损坏时，缓存命中和母版导出都失败，不忽略保护。

## 响应时间

同一约 1200 万像素 NEF，1400px 预览；以下为独立 CLI 后端计时，不包括首次能力探测/Swift 编译、浏览器传输、候选事务或界面更新。测量由 `node test/raw-backends-check.mjs <public.NEF>` 完成。

| 本机首次测量 | Apple | LibRaw |
| --- | ---: | ---: |
| 导入与生成代理 | 1758 ms | 1790 ms |
| 首次预览 | 340 ms | 299 ms |
| 相同版本缓存预览 | 29 ms | 33 ms |
| 曝光改变后的预览 | 330 ms | 287 ms |
| 日常分享 JPEG | 1497 ms | 983 ms |
| 原尺寸 16 位 TIFF | 5427 ms | 5204 ms |

完整测试与网页导出并行时，复测导入为 4.8–5.2 秒、预览 0.4–0.8 秒、缓存 67–101 ms、母版 12.6–20.7 秒。以上是实际样片观察，不是通用时延保证。预览不重新解码；固定版本的相同请求合并到一个工作线程，取消某个请求不会中断仍有其他查看者的任务。只在最后一位查看者取消时停止共用任务。

## 网页验收

独立 QA 服务使用端口 3179。经浏览器真实文件选择器导入公开 NEF，自动打开共用后端编辑器；添加曝光步骤，修改为 +0.5 EV，查看试片并接受保存。默认「日常分享」实际生成 2048 × 1362 JPEG；「继续精修」实际生成 4256 × 2832 RGB 16 位 TIFF。界面显示成片已保存，项目导出记录及磁盘文件 metadata 均已核对。浏览器只下载 PNG 代理，不下载完整 RAW 到 Canvas。

## 回归与持续检查

完整 Node 测试、共享引擎、架构和插件检查作为提交门槛。新增测试覆盖平台选择、真实子进程错误/取消/超时、线性精度、缓存失效、源数据改变、分块、保护和网页导入。已有 App Server 取消测试改为等待真实 `turn/started`，保留中断与重试断言，避免会话准备阶段提前取消造成误报。

CI 增加 Linux 上的生成 DNG 真实解码，以及 macOS 上的两套真实后端、自动回退、已知渐变和完整导出检查。CI 结果以提交的实际 GitHub checks 为准。未验证所有相机、所有压缩方式、Windows 实机、9600 万像素最坏负载、广色域输出或相机风格匹配。
