# 代码结构与异步流程审查

审查基线：`a782a68`（最新主分支，含导航恢复）。未合并的 PR #9、#10 不属于已发布代码。重点覆盖网页照片状态、草稿、文件项目、模型请求、渲染与导出；没有运行付费模型画质评测。

## 需要修复的缺陷

1. **高：草稿保存不构成等待屏障。** `flushDraftSave()` 在 `draftSaving` 为真时直接返回。实际运行该函数并延迟存储响应，第二次调用已完成，而第一次仍在保存。恢复/清理草稿依赖这个等待，因此可能在旧保存落地之前切换工作区；存储失败也未阻止替换。恢复锁在等待之后才设置，连续点击还可能并行恢复。
2. **高：本机视觉调用缺少来源约束。** 文件项目与模型设置检查 Host/Origin，但审片、顾问、复评与组图接口没有相同入口保护。其他网页可提交 `text/plain` 的简单 POST，触发本机配置的模型调用。修复应允许本机网页和本机 CLI 的 JSON 调用，拒绝外站浏览器及重绑定 Host；云端继续由部署平台访问控制负责。
3. **中：相同文件项目可以并行打开。** `load()` 的异步取图与插入没有按项目合并在途操作。连续点击会重复执行 `onLoad`，并建立多余事件连接。恢复浏览器草稿时也没有释放被替换照片的文件项目连接与保存定时器。

## 结构改进建议（不等于已发生故障）

- **照片状态有两份。** `state` 和 `photoSessions` 通过 `saveCurrentPhoto`/`photoStateKeys` 手动复制。新增字段、跨照片异步结果需要记住复制时机。建议逐步将照片实体作为唯一编辑状态，界面仅保留选中照片 ID、面板和临时预览状态。
- **主入口职责集中。** `public/app.js` 为 3,584 行，包含导航、图像处理协调、顾问、存储、组图、导出和大量事件绑定。优先抽出存储控制器，再按导入、顾问与导出拆分；每一步维持原路径并运行浏览器验收。
- **样式依赖加载顺序。** 页面加载 16 个样式表，同一导航/面板选择器被多个文件覆盖。之前导航消失就是此类回退。建议按基础、布局、组件、响应式建立明确归属，删除已有替代规则后再合并，避免再加一层覆盖。
- **顾问请求重复计算当前画面。** `currentAgentPreview`、`annotationRegionStats` 和请求光度参照各自调用同步像素管线；有聚焦批注的视觉请求最多处理同一帧三次。建议捕获一次当前效果，复用给框选缩略图、区域统计和光度参照。尚未测量不同设备上的耗时，不能据此声称已出现卡顿。
- **画质验证与工程测试不同。** 现有真实样张、共享引擎比对和浏览器门禁有价值，但不能据此证明模型建议有审美提升。视觉建议需独立记录样张、原片/成片、模型版本、失败建议与人工判断。

## 本次处理范围

先处理已确认的保存/恢复、入口保护与项目加载生命周期，不重做导航、调色配方或像素引擎。结构拆分建议保留为后续逐步重构范围。

## 修复与验证

- 草稿保存移入独立 `draft-autosave.js`，重复 flush 共享同一个 Promise，包含保存期间的新修改；失败保持待保存状态。恢复入口提前锁定，并在全部原片解码后再次等待保存。存储失败时停止切换/清理；切换成功时释放旧项目事件连接与定时器。
- 文件项目按 ID 合并重复打开，不同项目依次导入；失败不会阻塞下一个。保留既有版本、冲突与同步行为。
- 四个本机视觉接口在调用模型之前检查 Host、Origin、跨站来源与 JSON 内容类型。本机 CLI 可不携带 Origin；浏览器同源请求及云端原流程保留。
- 修复前的回归用例实际失败：相同项目执行两次导入；外站简单 POST 返回 200 并到达模拟模型。草稿函数独立复现第二次 flush 在首次写入完成前返回。
- 修复后 `npm test`：374 项通过，零失败/跳过；15 个共享像素模块保持一致。浏览器验收通过延迟 IndexedDB 完成、连续恢复点击、配额失败与重试，以及 1280×800、1280×577、390×844、320×720 的原导航流程。

结论：本次确认的异步和本机调用缺陷已修复。仍建议逐步处理上述状态归属、入口拆分、样式归属与重复计算；没有把这些建议当作已复现的故障，也没有据此宣称整套代码无其他缺陷。
