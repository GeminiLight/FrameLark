# 用真实修前／修后照片评测 FrameLark

这套评测回答两个问题：**Agent 修完是否比输入更值得保留？与真实人工修后版本相比，差距在哪里？** 它不把亮度、饱和度变化或工具执行成功当作审美提升。

## 数据选择

| [Play Raw](https://discuss.pixls.us/t/about-the-play-raw-category/11956) | 用户确实修不好的 RAW／JPEG，以及社区多种处理和 XMP／PP3 | 已核查 8 个候选主题。逐帖核对原图与修后图许可；原图 CC0 不自动覆盖他人的修后图。当前论坛默认贡献许可含 NC |

## 复现下载

在仓库根目录运行，选择仓库外的新目录。先阅读上述图片研究许可证，确认只做非商业研究：

```sh
node scripts/fetch-retouch-eval.mjs --output /absolute/path/FrameLark-eval --research-only
```

下载器按固定清单取 8 张 RAW 与 16 张专家 TIFF，保存两种许可证及文件归属表，并核对长度和 SHA256。已核对的文件复用；不一致的已有文件保留并报错。它只准备数据，不调用模型或生成评测分数。

## 首轮协议

1. 固定输入、源文件校验、代码提交和工具版本。先约定表达目标；同图只计一例，人工制造的坏曝光、同张不同裁剪不算独立照片。
2. **自主修图轨**：编辑 Agent 只获取 RAW／原片、用户意图和 Skill；不读取专家图、参数或评审意见。原片可以胜出。首轮各图最多两次试修，未达标的候选照常计入结果，不只挑成功图。
3. 主轨保留构图，让光色收益独立可见；裁剪另设一轨，记录删除的信息。RAW 基线注明固定显影后端，不能把它冒称相机直出 JPEG。参考 TIFF 按内嵌 ProPhotoRGB ICC 转 sRGB，而不是重贴色彩标签。
4. 将输入与实际结果用相同色彩处理、相同观看尺度制作匿名 A/B，逐图随机左右。另一位可看图的 Agent 不读角色、作者解释或自评，先锁定 A/B／并列判断和具体可见理由。源尺寸纹理另用等比例区域验证；普通小图不称 100% 验收。
5. 票锁定后才揭示原片／Agent 角色和两位专家参考。分析差距与内容保持，不要求复制某一位修图师。**参考跟修轨**必须另记 referenceSeen=true，不与自主轨混算。
6. 报告改善／无明确收益／变差／无法执行，分别列出试修、自审交付状态、独立比较与人工投票。样本过少或弱偏好时不下总体能力结论；Agent ready 和多数投票都不代表用户认可。

## 计分与失败记录

主要结果是匿名比较的胜／平／负与理由。强度区分明显和轻微；需要继续修的结果即使优于原片，也不是完成交付。检查主体、光色关系、肤色／材料、平滑区域、纹理、边缘、噪声和内容保持。

PSNR、SSIM、ΔE 只用于已确认配准、同尺寸、同色彩路径的参考接近度，不能单独证明更美。Apple 与 Lightroom RAW 显影边界、不同裁剪／方向和多帧信息差异不明时，禁算或明确限制像素指标。几何和身份／文字改写单列为失败，不能被漂亮配色抵消。

每轮保留输入 SHA256、实际编辑项目、候选／版本、实际导出路径与哈希、编辑者目标和自审、匿名映射、独立判断、参考差距和人工反馈。失败保留，不删掉后重算通过率。

## 扩充顺序

先用小集暴露失败，补好再扩大：FiveK 按题材、真实曝光问题和光线分层；PPR10K 按**组**取样和划分，包含不同肤色、混光和连续交付；Play Raw 先确认输入角色与参考版本确有可见收益，再纳入。已看过和用于调 Skill 的照片进入开发集；下一轮另取未参与优化的新照片，不把预留两张宣传成大规模盲测。

组图另测主题、近似原片取舍、九格节奏和昼夜协调。PPR10K 的组内光色一致性不能替代朋友圈九宫格的编辑审美。

## 本轮状态

2026-10-08：8 张 FiveK 原片与 C／E 两位参考已准备，6 张已实际自主试修并完成匿名比较，2 张预留未执行。该子集是刻意挑选的开发试验，不是 FiveK 官方测试集，也不能估计总体胜率。详细图像、完整诊断和研究报告保留在本地实验目录；最终结论以该轮匿名评审记录为准。

初轮观察：3 张明确偏好 Agent、1 张轻微偏好、1 张并列，1 张在换位后的另一位评审中发生分歧，未确认收益。原始票（Agent 4／并列 1／原片 1）保留，不用复核覆盖负结果。专家参考差距集中在岩壁与砖楼的受光材料、小鸭的主体辨认，以及旧琴与大面积红绒之间的主次；这只说明开发小集上的问题，不证明 Skill 总体审美或组图能力提升。
