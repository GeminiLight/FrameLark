# 系统审核与恢复边界修正

审核基线：`adbd24b38082a6c5149cf54304f38ef816c90230`。本轮检查 Web 工作台、文件项目与组图、CLI/Skill、RAW 派生缓存、插件安装和官网构建。原完整测试 679 项通过，但缺少以下跨边界与失败窗口的覆盖。

## 已复现的问题

| 问题 | 实际影响 | 修正边界 |
| --- | --- | --- |
| 浏览器组图漏传编辑文档，增量又写入旧层 | 已有步骤不进入模型图像/组图预览；接受增量后，编辑器与导出可能看不到变化 | 图片、放大对照均使用当前文档；增量转成现有原子命令，经单图控制器保存；旧滑块只描述基础层 |
| 共享组图的延迟操作与打开请求没有页面所有权 | A 的保存或通知可覆盖后来打开的 B；较慢的旧打开请求抢回选择 | 打开请求与页面任务分别持有代次和组图身份，旧回复不能改动新页面或释放其保存状态 |
| 服务端读取单图两次后拼组图响应 | 旧版本标签、旧方案状态与新预览 URL 混用 | 上下文、版本、预览地址使用同一快照，预览指向明确版本与 revision |
| 导出文件落盘与完成记录之间取消 | 同一任务重试稳定遇到 OUTPUT_EXISTS，无法恢复 | 写入前持久化尝试；未完成项重试使用新名称，保留任何旧文件；已完成项按记录路径和 hash 复用 |
| 偏好档案写入、读取约束不一致 | 编辑成功后档案无法读取；合法 500 条记录也可能被格式化写入推过读取预算 | learn/edit/read 共用字段上限，读写共用有界 UTF-8 字节预算，紧凑保存；超限写入保留原字节，旧合法长字段与大档案可正常维护 |
| RAW 派生缓存只要能解码就被信任 | 缓存被替换成合法黑 PNG 后，PNG/JPEG 导出错误，原片与母版却未变 | 校验缓存身份和尺寸；缺失或不匹配时从验证过的源/母版重算，不让派生缓存成为像素权威 |
| 两种插件并发安装只靠 catalog 原子替换 | 两次都返回成功，最后却丢掉一种来源登记 | 同一 Codex profile 的读取、准备、登记、安装与回滚共用跨进程事务锁 |
| 本地插件安装先切来源、后准备依赖 | 准备失败后留下新来源；推荐的 Release 重试入口又拒绝本地来源 | 先暂存并准备依赖，之后切换；失败恢复原来源与选择，无法自动恢复时保留私有记录，提示本地重试入口 |
| 官网构建允许输出与维护来源重叠 | 先删除输入源码，再因缺失页面而失败 | 删除前校验输出与来源及其祖先/子目录不重叠，识别真实路径和符号链接别名 |

这些问题分别在拥有行为的模块修复，没有修改共享像素内核或把项目权威逻辑复制进 HTTP/界面适配器。普通浏览器组图处理能在常规精修中完整表示的照片；需要协作精修的项目及尚未保存的原生输入继续走共享组图。

## 验证方式

新增回归先重放原失败，再验证修正。档案与导出使用真实临时项目和实际文件；安装使用实际维护包及隔离的 Codex 状态适配器，控制并发、依赖失败和回滚窗口；构建在源码副本上检查删除保护。没有修改用户照片、偏好档案或真实插件配置。

`test:series-documents` 在真实浏览器中检查两个文件项目：模型输入图片确实包含已保存曝光步骤、增量确实成为可重放步骤并写盘、整组撤销恢复已保存版本、桌面与手机布局可用。它使用生成的技术 PNG 和固定协议夹具，并已加入 CI；这不是模型审美评测。

最终完整测试 **746/746 通过**；45 个共享模块、知识索引、架构与 full/eye 插件检查通过。真实浏览器的组图配方、文件项目协作、共享组图及导航检查通过；新增组图流程包含真实保存回执延迟期间的视图切换。分发另验证真实维护 ZIP 的原生依赖新装、重复更新和旧缓存删除后的原位恢复。GitHub 的跨平台、容器与浏览器门禁随 PR 保留。

## 覆盖与限制

深查了状态所有权、版本绑定、失败恢复、原片保护及分发事务，结构检查另覆盖仓库归属和导入/文档链接。共享像素内核沿用已有行为与回归；本轮没有重做全平台手工体验、摄影审美评测、视频处理或第三方模型能力评估。

前端 app.js 仍协调多个界面流程，测试中部分协调器使用受控 DOM/网络边界验证。新增真实浏览器流程补足关键跨模块链路，但不把所有单元检查当成完整产品验收。后续拆分应沿现有照片、项目、组图的所有权边界进行，避免同时重写像素和持久化契约。

安装锁串行化 FrameLark 的两个入口。外部 UI 的来源、版本和启用选择在提交、成功及回滚前再次核对；Codex CLI 没有跨 UI 的整体事务接口，无法保证所有外部程序在任意两个系统调用之间都不能修改配置。无法确认恢复所有权时保留私有记录和原安装备份，报告未完成。

修正后的完整插件为 0.1.14，内容未改变的独立摄影眼保持 0.1.1；构建安装包与合并代码不等于发布 GitHub Release。
