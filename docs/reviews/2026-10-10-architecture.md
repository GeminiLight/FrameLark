# 架构审核与恢复契约修正

本轮以 `5b0e8677190213a9c568afa2c85db6e51fbe4147` 为基线。基线完整测试 746/746 通过；进一步用真实文件、多个进程和浏览器检查异常恢复与跨入口契约，复现了以下问题。审核覆盖工作台、CLI/Skill、单图与组图持久化、偏好档案、审核交付、分发构建与安装；修复集中于拥有这些行为的模块。

## 已复现与修正

| 问题 | 原行为与影响 | 修正 |
| --- | --- | --- |
| 死进程锁恢复使用过期观察 | 两进程都基于 revision 1 保存成功，最后只有一份 revision 2；恢复者删除另一进程刚取得的锁 | 共用恢复锁，重新核对目录身份与所有者；写入和释放持有本次令牌。相同 revision 只能成功一次 |
| 空 owner 锁无法恢复 | 陈旧空 owner 的单图项目始终 PROJECT_BUSY | 对陈旧缺失、空或损坏所有者统一恢复；活旧 PID 锁保持有效，owner 写入失败清理自己的目录 |
| 偏好档案进程中断留下永久锁 | 实际 CLI 在持锁时被终止，原档案可读但后续 edit 一直 PROFILE_BUSY | 档案使用同一锁边界；死进程和陈旧旧格式锁可恢复，活写入者仍互斥 |
| 当前版本审核状态虚报交付 | reviewed 项目有阻断问题，自审 ready 且未记录解决仍显示 delivered | 当前版本与候选共用审核资格；检查适用诊断、独立身份及阻断结论，保留人工接受能力 |
| 独立暗房下载仅检查字面路径 | 已登记 PNG 被替换为项目外文件链接，实际下载返回外部字节 | 两入口共用真实目录、文件位置与记录身份检查；不返回项目外链接内容 |
| 单图成片记录不能随项目搬迁 | 原片、版本和导出文件完整，重登记后旧绝对路径使下载失败 | 新内部成片记录相对路径，旧有哈希记录按当前内部文件身份恢复；外部输出保持外部身份 |
| 独立 Skill 安装忽略 CODEX_HOME | 指定另一个 Codex profile 后仍写入默认 profile；旧版备份也写错位置 | 默认安装、旧版迁移与备份共同遵循选定 profile；显式目标目录仍按用户参数 |
| 安装首次观察可认领后来的选择 | add 成功与首次 snapshot 之间版本、来源、缓存或启用选择变化，安装器仍返回成功 | 首次基线必须匹配目标来源、版本、缓存、维护字节与启用选择；未确认的状态不能授权回滚 |
| Release 的 dist 链接可覆盖来源 | 输出通过 dist 链接指向维护 Skill，构建成功却替换 Skill 目录并删除旧备份；交叉复核又确认清单或 ZIP 的硬链接原位写入会修改源文件 | 检查真实输出及实际删写位置；拒绝与维护来源、祖先或 Git 元数据重叠；清单与 ZIP 用独占临时文件再替换，保留硬链接的原文件，支持合法独立输出 |
| 12 张组图请求超过自身接口上限 | 每张 JPEG 约 465k 字符，均合法，但真实浏览器总请求 5,591,469 字节被拒绝，provider 调用为 0 | 根据完整 UTF-8 元数据分配整组图片预算，缩小超预算分析预览。相同 12 张请求 2,836,245 字节，全部到达接口并准备完整预览 |

没有修改像素内核或项目源图。文件锁与成片解析属于可独立安装的 Skill；HTTP 入口和工作台只使用这一边界。组图预览保留当前编辑文档，容量调整发生在分析图编码阶段。

## 验证

回归先重放原失败再修正。锁测试使用真实子进程和真实项目，控制旧观察的调度窗口；偏好测试终止实际 CLI 写入进程。成片测试通过工作台与带会话令牌的独立暗房请求验证位置、搬迁、哈希及旧记录行为。安装测试使用维护包、隔离文件系统及状态适配器，覆盖来源变化、禁用、删除、缓存变化和失去回执；没有改变真实 Codex 安装或配置。

`test:series-inputs` 使用 12 张生成的细节 PNG、浏览器 Canvas 编码、真实 HTTP 服务和固定协议 provider，验证所有成员均进入请求且满足单图与总字节预算。`test:series-documents` 继续验证已保存步骤进入模型图像、增量写盘、回执延迟期间的界面操作及整组撤销。两个流程均纳入 CI，固定内容不用于评价模型审美能力。

最终完整测试 **798/798 通过**，无失败或跳过；45 个共享模块、架构与知识索引、full/eye 插件和 v0.1.15 发布包检查通过。实际浏览器验证覆盖 12 张输入容量、已保存组图配方、文件协作与导出。独立复核另重放锁的所有权变化、成片迁移和两种构建硬链接，修正后均符合相应契约。跨平台、容器、浏览器与 RAW 检查由 GitHub CI 在 PR 最终提交上核验，合并依据同时记录于对应 PR。

## 覆盖与保留限制

进程所有权按真实写入入口核对：图片 worker_threads 只计算像素，项目提交由主线程执行；整组导出子进程拥有自己的锁 PID。因此本轮不增加没有生产调用依据的线程租约或心跳机制。

旧成片没有可用哈希且绝对位置失效时，无法证明搬迁后文件身份；保留现有文件并要求重新导出。哈希和工作流记录验证状态与文件身份，不证明实际看图或审美质量。人工直接接受继续可用。

Codex CLI 没有与外部 UI 共用的整体安装事务。首次观察到未启用状态时，无法区分安装策略禁用和用户后来禁用；此时保留当前选择及完整私有备份，报告恢复未完成。取得有效目标基线后的常规依赖或字节校验故障继续恢复原安装。任何两个系统调用之间的外部修改仍无法被整体锁住。

前端 app.js 仍协调多个流程，后续拆分应按现有照片、项目和组图的状态所有权进行。此次没有进行全平台手工体验或新的摄影审美评测；已有像素、RAW、分发和浏览器检查继续作为合并门禁。完整插件更新至 0.1.15，独立摄影眼内容未改，保持 0.1.1；提交合并不等于发布 GitHub Release。
