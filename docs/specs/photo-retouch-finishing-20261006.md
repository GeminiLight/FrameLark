# 精修与组图执行优化 · 2026-10-06

这轮针对“规则完整，但真实照片仍不好看”的交付失败。基线为 photo-retouch 0.1.7：已经包含主题先行、逐张打磨、复审和九格检查，但历史审核仍曾把未完成的主体/材质问题列成轻微，并把小幅改善当作成片依据。摄影眼的参考图板设计成功不能证明这条精修链路的照片质量。

## 本轮改变

- 在入口增加简短的[成片执行卡](../../skills/photo-retouch/references/finishing-workflow.md)：先写表达、共同观感、实际取舍和每张可检查的目标，再选择原片像素处理、AI 综合编辑或保留原片。
- 按原目标复评，区分“改善”与“达到目标”，照片先去掉文案与版式再审；单张、整组和设计质量分别判断。定调文档的 Agent 保存命令补上 `--require-audit true`，与已有审核流程一致。
- 新增本地输入联系表工具，处理宿主独立图片输入数不足的情况。完整归正、缩小每张原片，保留格位、来源hash及有效边界，不裁剪、不写回原片；对应 ID 只存 JSON，不写到位图。此工具只准备输入，不修图也不调用模型。
- 插件版本更新为0.1.8；保留原来的摄影眼、修图引擎、用户保护与偏好记录语义。
- 合入最新版RAW显影后，补清JPG快速浏览、入选RAW实际后端检查和显示预览输入路线；同步三处仍写“RAW先转JPEG”或“只有8位工作图”的旧参考。当前目录枚举尚未覆盖RAF，按明确文件列表导入；不把JPG/RAW同帧算成两张，不将RAW数据、显示预览和AI小图板混称同一精度。本轮没有对南沙RAF执行显影或母版导出。

## 实际验证与范围

| 验证 | 已观察到什么 | 不据此宣称什么 |
| --- | --- | --- |
| 独立审片：旧混合九格与两张同构图对照 | 未给旧审稿或预设答案，实际判返修；饮品体积、人物与天幕主次成为阻碍，单张问题与整组排列分别说明 | 不是未见数据上的审美能力评测，也不是用户满意 |
| 独立边界例：暖木咖啡 | 可以保留原片，不为了流程要求新增调色或生成 | 不证明所有暖色、深色饮品都无需修 |
| 独立边界例：限本地工具的人物动作照 | 区分可改善的构图/明暗与不能由锐化恢复的模糊，尊重本地处理范围 | 没有实际执行或证明工具能恢复丢失细节 |
| 九图综合试片 | 当前宿主九独立输入被参数校验拒绝；用一张原片联系表实际一次生成九格，输入角色按格出现 | 天空、背景人物和局部结构有改写，1254×1254整板不足以称九张高清成片；未获用户接受 |
| 输入联系表测试 | 9张数量与来源保持、EXIF方向、完整边界、已有目录保护、缺图/坏图拒绝、ID不写入图片 | 只验证输入准备；不能保证生图输出零重绘或零文字 |

九图试片出现了编号泄漏，因此工具改成无字输入；无字路线通过本地测试，本轮没有再生成一张来宣称问题已经消失。生成尝试与完成次数分别记录，模型版本与费用未确认。私人原片、两轮审片记录和试片均保留在用户照片目录的新实验文件夹，没有打包或上传到仓库。

行为用例见[回归场景](../../skills/photo-retouch/evals/finishing-quality.json)。它们检验取舍、目标未完成时的处理与工具边界，不进行自动审美打分。后续应在新场景中用实际成片及用户明确接受验证，不能因知识页、插件或测试通过就宣布已经具备稳定审美。
