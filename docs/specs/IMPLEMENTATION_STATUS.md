## 验收边界

实际 T07 已走通：文本更新原步骤 → 完整预览/接受 → 独立 Skill 两项候选 → 只选择对比度 → 修改已接受参数 → 暂停 → 重排 → 删除 → 撤销 → 刷新 → 导出。原 ID、0.25 EV 与 70% 强度/高光范围在语言更新后保留，后续手动改到 0.28 EV。第二张保存期间切回第一张，两个配方没有串写。390×844 与 320×720 没有横向溢出，步骤按钮最小高度 44 px，完成后撤销 viewport 覆盖。

64 步是文档上限，不是实时性能承诺。8 位源解码与旧兼容基础保留；新步骤中间采用 Float32。蒙版为明度/几何范围，冻结参考限于绑定源身份的原片。含文字或最终保护资源的便携交换继续明确拒绝，原文件项目完整保留。

基准脚本 `scripts/benchmark-edit-stack.mjs` 固定尺寸 560×420 / 1400×1050、1/8/24 步和工具顺序，分别记录冷处理、三次相同热处理，以及独立预热后的首/中/末步修改。工作字节估计与 RSS 样本不称为真实内存峰值，耗时不称为审美质量。

## 最终证据与性能

- [导出快照](evidence/export-snapshot.json)：实际 PNG 1448×1086，解码 RGBA 与 captured version 逐字节相同。导出为 0.27 EV，当前已改到 0.28 EV，原片校验不变。IAB 未交付自动化 download event；文件生成、开始下载的页面状态与本机产物均已确认，不把事件等待超时当成文件未生成。
- [独立 Skill 交换往返](evidence/portable-roundtrip.json)：安装副本 project-export/project-import，步骤、源和同网格像素保留。
- [浏览器真实 CAS](evidence/browser-cas.json)：旧 writer 被拒绝，最新值与未保存输入保留；旧 DB 版本打开被拒绝。
- [Apple M3 固定协议基准](evidence/benchmark-m3.json)：560×420 的 1/8/24 步冷处理约 117/509/986 ms，相同配方热处理约 15–16 ms；1400×1050 的冷处理约 668/2691/6432 ms，相同配方热处理约 93–95 ms。24 步 1400 网格末步修改约 488 ms，首/中步仍约 6.4 s。没有宣称 150 ms 交互已实现，复杂栈早段修改仍需优化。
- 导出复用 captured native version ID，重开按持久 export records 标记，不再把旧配方快照作为新的当前版本导入。只有导出记录变化时可推进 revision 并保留正在编辑的输入；配方、意图、批注或选择改变仍拒绝旧结果。
- 命名快照可引用已有历史配方，不能用任意新 recipe 绕开命令写入口；指定范围也拒绝共享蒙版或 cascade 间接改变其他步骤。
- 独立 Skill 使用与 #16 同源码校验的 2 worker / 8 queued / 120 秒渲染池；断开响应取消并等待真实终止。
