# 可编辑修图栈：实施规格

版本 1.1，输入规格为 [设计稿 1.0](editable-stack-input-v1.md)。源码基线 `f130dfc`；旧实现完整测试 414 项通过。本文件是实施契约，完成状态以验收记录为准。

## #16 后的重新判断

当前实施已重基至 `e3b7a19`（#16），其照片状态、渲染和导出边界是实施前提，不把原 SDD 的 `app.js` 字段复制方案带回来。

- **状态归属**：`photo-state.js` 的照片对象持有 recipe；活动编辑器仅投影这一对象。选择、展开和蒙版显示属于该照片的 viewState。文件项目更新继续使用每张照片的更新范围，不能新增全局“正在更新”开关抑制其他照片保存。
- **渲染任务**：文件预览、保护准备和导出复用 `createProjectRenderPool`。保持同时最多 2 个 worker、最多 8 个等待任务、包含等待的 120 秒期限；取消必须等待真实终止，失败终止继续阻止新任务。栈的 latest-wins 在所属预览范围取消/丢弃旧任务，不能启动第二套不受限队列。
- **导出快照**：导出服务捕获完整 recipe、源、frameSpec 和身份；排队后不得重新读取当前照片或当前滑杆。沿用两种导出共同的 128 MiB 结果缓存预算与中断清理，Float32 工作缓冲预算是另一个约束。
- **依赖方向**：纯文档/像素模块不导入浏览器协调器或 Node；项目模块不导入 HTTP formatter。共享结果投影通过独立 Module，CLI 和 HTTP 使用相同文档校验。

增加 #16 验收：两张照片各有不同配方，在另一张项目更新时继续编辑仍标记保存；暂停一个导出任务后更改/切换照片，输出保持点击时的配方；多个栈预览遵守并发与取消限制，过期结果不能提交；现有导出、导航和协作浏览器门槛继续通过。

## 规格判断

设计稿准确识别了当前工具图与持久像素栈的区别，保留旧渲染、候选事务、保护和四页签的方向合理。R01–R12、T01–T11继续作为需求和验收编号。它足以指导拆分，但以下内容必须收敛为可执行契约，不能只照着字段示意实现。

1. `schema:3` 用于可编辑文档和首次包含该文档的文件项目；`pipeline`、工具语义版本、内核版本分别固定。旧 v1 操作与新 v2 像素节点不共用参数解释。
2. 文档的兼容基础保存经过严格校验的不可变状态快照与身份；文件项目额外验证来源属于本项目。浏览器不依赖不可访问的文件版本 ID。旧 `toolRuns` 只保留来源，不自动还原成节点。
3. 明度保护默认取该节点输入；冻结参考首轮明确指不可变原片，并绑定源身份。任意历史版本的外部冻结资源不能伪称可用。几何蒙版保存原片坐标及仿射基底，不以外接框替代旋转选区。
4. 顺序渲染使用共享 Float32 内核，v2 参数仅作用于该节点。混合为 `I + opacity * mask * (F(I)-I)`；一次显示编码，alpha 不变，严格旁路保留原 RGBA。风格展开成带固定预设来源的子步骤。
5. 兼容基础、固定构图、顺序效果、文字和最终保护依次处理。无法安全映射的旧参数锁阻止新的像素变更，使用既有显式解锁候选；最终区域保护继续在最后合成。旧版本和保护参考不原地升级。
6. 文档命令是唯一写入口；旧快照 API 必须携带或明确拒绝文档，不能静默覆盖。文件首写备份、revision、幂等请求和预览身份沿用现有事务。IndexedDB 在同一读写事务内检查保存 revision。
7. 64 步、蒙版深度 8 和输出预算是受校验的资源上限，不能宣传为所有主机均实时。先保留受限缓冲和任务队列，记录实测性能；不把 150ms 当成已达成承诺。

## 工具与节点

曝光、影调、色彩、细节、氛围的 v2 工具声明中性值、参数边界、颜色空间、邻域与输出策略。构图独立于可重排效果列表。风格保存展开后的参数与预设内容身份；原先光色、细节、风格均能通过兼容基础完整重放，不更改旧算法。

步骤保存稳定 ID、工具及语义版本、标题、参数、enabled、opacity、maskRef、依赖、groupId。蒙版保存不可变的 id+version、表达式和参考；修改共享范围默认只替换当前步骤，另有明确的全部使用者更新。分组只提供命名、折叠和开关，不提供含混的组不透明度。

普通串行后继不产生硬依赖。真实依赖必须在列表中位于消费者之前；命令不能偷偷排序。关闭、删除和移动依赖生产者时返回具体消费者。批量命令先在副本全部验证，再形成一次撤销事务。撤销、重做、命名版本和 viewState 分开。

## 必须完成的用户流程

使用测试照片，通过文本产生“暗处提亮，保护已有高光”的候选；预览蒙版和效果，部分采纳；继续修改已接受步骤的 EV、强度和范围，关闭、重排、删除、撤销；再用语言更新同一 ID；保存、刷新、打开文件项目、经 CLI 读取/修改、交换后仍可编辑，并导出实际图片。

任何阶段只有曝光示例成功、只有记录列表或只有最终参数可编辑，都不能标记全部完成。尚未运行的实际 UI、跨端和画质检查明确保留为未验证。

## 产品依据

Photoshop 提供可编辑滤镜、顺序和可见性，darktable 以有顺序限制的像素模块处理照片；Lightroom 的蒙版与历史/快照可借鉴，但历史不是可重排效果栈。这里采用小型非破坏性操作栈，并保持照片工作流的固定构图阶段。

- [Photoshop 智能滤镜](https://helpx.adobe.com/photoshop/desktop/effects-filters/smart-filters/apply-and-manage-smart-filters.html)
- [Lightroom Classic 蒙版](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/masking.html)
- [darktable 像素管线与顺序](https://docs.darktable.org/usermanual/development/en/darkroom/pixelpipe/the-pixelpipe-and-module-order/)
- [Sharp 操作契约](https://sharp.pixelplumbing.com/api-operation/)
